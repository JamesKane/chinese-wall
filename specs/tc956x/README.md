# Toshiba TC956x PCIe 2.5 GbE Ethernet Bridge Functional Specification

**[HW]** Target hardware: the **Toshiba TC956x** (specifically the TC9563 PCIe switch and dual-port Ethernet controller package integrated on the Radxa Dragon Q8B board, connected to Qualcomm SC8280XP PCIe Controller 4). The TC956x integrates a PCIe Gen3 switch (PCI IDs `1179:0623`) with an internal downstream bridge (Port 3) feeding a multifunction PCIe Endpoint exposing two Ethernet Physical Functions (`1179:0220`, Subsystem `1179:0001`, PCI Class `0x020000`). Each physical function drives an independent Synopsys DesignWare XGMAC2 v3.01a 10G-class MAC core, a Synopsys DesignWare XPCS physical coding sublayer, a Toshiba SerDes Physical Medium Attachment (PMA) wrapper, and an external Qualcomm Atheros QCA8081 2.5GBASE-T / 1000BASE-T / 100BASE-TX / 10BASE-T Copper PHY attached via MDIO and SerDes (2500BASE-X / SGMII).

**[POLICY]** Every statement and table in this specification suite is tagged with one of the following requirement classifications:

- **[HW]**: Required by the hardware or board firmware. Any clean-room driver implementation must obey these constraints.
- **[POLICY]**: An operating-system or driver design choice (such as ring sizes, timeout intervals, or buffer sizes). Informative only.
- **[ABI]**: Required for compatibility with UEFI firmware state, EEPROM layouts, or standard hardware interfaces.

## Critical Architectural Summary for Clean-Room Implementers

1. **[HW]** **Cross-Function BAR4 Dependency**: Only Function 0 (`0004:03:00.0`) exposes the chip-wide Special Function Registers (SFR) for clocks (`NCLKCTRL0` at `0x1004`, `NCLKCTRL1` at `0x100C`), resets (`NRSTCTRL0` at `0x1008`, `NRSTCTRL1` at `0x1010`), eMAC mode control (`NEMAC0CTL` at `0x1070`, `NEMAC1CTL` at `0x1074`), and GPIOs (`0x1200–0x1214`) in its BAR4 window. Function 1 (`0004:03:00.1`) must either access Function 0's BAR4 for clock/reset/mode/GPIO control or rely on a shared parent bridge manager bound to Function 0.
2. **[HW]** **Unclocked / In-Reset MMIO Fatal Bus Abort**: Reading or writing any register inside an internal IP block (MSIGEN, XGMAC2, XPCS, or PMA) while its clock bit in `NCLKCTRL0`/`NCLKCTRL1` is `0` or its reset bit in `NRSTCTRL0`/`NRSTCTRL1` is `1` causes an unacknowledged internal AXI transaction that aborts the PCIe Memory Read/Write TLP and triggers an immediate fatal system error (SError) on ARM64 hosts.
3. **[HW]** **Mandatory DMA Host Address Offset (`+0x10_0000_0000`)**: The XGMAC2 DMA masters sit on an internal AXI4 bus where lower addresses map to on-chip SRAM and registers. Host PCIe memory is reached through an AXI-to-PCIe Translation Address Map (TAMAP) window configured in BAR0 (`+0x0800`) covering AXI addresses `0x0000_0010_0000_0000` through `0x0000_001F_FFFF_FFFF` (64 GB) and translating them to PCIe bus addresses `0x0000_0000_0000_0000` through `0x0000_000F_FFFF_FFFF`. Every descriptor ring base address, buffer address, and tail pointer programmed into XGMAC2 DMA registers or descriptors must have `0x0000_0010_0000_0000` added to the 36-bit host physical/IOVA address.
4. **[HW]** **Station MAC Address Preservation**: Asserting the per-port MAC reset (`NRSTCTRL0` bit 7 or `NRSTCTRL1` bit 7) or the XGMAC DMA software reset (`DMA_MODE` bit 0 `SWR`) clears the station MAC address registers (`MAC_ADDR0_HIGH` at `+0x0300` and `MAC_ADDR0_LOW` at `+0x0304`) back to `ff:ff:ff:ff:ff:ff`. Because UEFI firmware pre-programs the factory MAC address before OS handoff, the driver must read and save `MAC_ADDR0_HIGH` and `MAC_ADDR0_LOW` (after enabling MAC clocks and deasserting reset if needed, before issuing a fresh reset pulse or `DMA_MODE.SWR`) and restore them afterward.
5. **[HW]** **Power-On Default `NEMACxCTL.SP_SEL` Trap**: At power-on reset, `NEMAC0CTL` (`0x1070`) and `NEMAC1CTL` (`0x1074`) default to `SP_SEL = 8` (10G USXGMII). Even if the driver only intends to run at 2.5G (`2500BASE-X`) or 1G (`SGMII`), `SP_SEL` must be explicitly programmed (`4` for 2500BASE-X or `5` for 1G SGMII) prior to executing the 5-step PMA initialization sequence, or the SerDes lane will never lock.
6. **[HW]** **Cold-Port QCA8081 SerDes FIFO Reset**: While UEFI initializes Port 0 during boot (for PXE), Port 1 is left cold. On every link-up transition of the QCA8081 PHY (MDIO address `0x1c`), the driver must toggle the SerDes FIFO reset bit (bit 11, `0x0800`) in Clause 45 MMD 1 register `0x9072` at the companion SerDes MDIO responder address `phy_addr + 1` (`0x1d`), or no frames will pass across the SerDes link.
