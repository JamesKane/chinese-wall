# 02: I²C Controllers

Sky1 has eight I²C controllers in the FCH domain. They are the Cadence
I²C IP, revision **r1p14**. This section gives the register map and
the transfer sequences a host (master) driver needs, plus the Sky1
integration. Target (slave) mode exists in the IP but is not described.

## 2.1 Instances

| Bus | Base | Size | IRQ (GIC SPI / GSIV) | SCMI clock | FCH reset index | Pin group |
|---|---|---|---|---|---|---|
| I2C0 | `0x04010000` | 64 KiB | 286 / 318 | 253 (`FCH_I2C0_APB`) | 18 | `pinctrl_fch_i2c0` |
| I2C1 | `0x04020000` | 64 KiB | 287 / 319 | 254 | 19 | `pinctrl_fch_i2c1` |
| I2C2 | `0x04030000` | 64 KiB | 288 / 320 | 255 | 20 | `pinctrl_fch_i2c2` |
| I2C3 | `0x04040000` | 64 KiB | 289 / 321 | 256 | 21 | `pinctrl_fch_i2c3` |
| I2C4 | `0x04050000` | 64 KiB | 290 / 322 | 257 | 22 | `pinctrl_fch_i2c4` |
| I2C5 | `0x04060000` | 64 KiB | 291 / 323 | 258 | 23 | `pinctrl_fch_i2c5` |
| I2C6 | `0x04070000` | 64 KiB | 292 / 324 | 259 | 24 | `pinctrl_fch_i2c6` |
| I2C7 | `0x04080000` | 64 KiB | 293 / 325 | 260 | 25 | `pinctrl_fch_i2c7` |

- **[HW]** Interrupts are level-high.
- **[HW]** One clock per controller. It is both the register clock and
  the bit-rate reference (§2.4). Get its rate from SCMI
  (`CLOCK_RATE_GET`, sky1-soc 01). Do not assume a value.
- **[HW]** One reset per controller, active-low in the FCH reset
  controller (sky1-soc 02 §2.1.2). Release it before touching registers.
- Sensor-hub (`sf_i2c*`) and power-management (`PM_I2C*`) I²C buses are
  separate blocks owned by other processors. They are not covered here.

> OPEN QUESTION: The input clock rate is not given anywhere in the
> sources. Read it at run time. If SCMI reports 0, the divider maths below
> cannot be done and the bus must not be started.

### 2.1.1 ACPI description

**[ABI]** `_HID` `CIXH200B`, `_UID` 0–7. The device carries:

| Object | Content |
|---|---|
| `_CRS` | `Memory32Fixed` (base, `0x10000`), one `Interrupt` (level, active-high, GSIV), and a `PinGroupFunction` naming the pin group (05-pinctrl) |
| `CLKT` | One entry: SCMI clock ID of the table above, empty name |
| `RSTL` | One entry: `RST1`, index 18 + *n*, name `"i2c_reset"` |
| `_DSD` | `"clock-frequency"` (integer, Hz; 400000 in the published example) and `"ClockName"` (string, for example `"fch_i2c0_apb"`) |

- **[ABI]** Child devices on the bus (for example the PD controller,
  04-usb-pd-rts5453) use the standard ACPI `I2cSerialBusV2` resource with a
  7-bit address and the bus-controller path.
- **[POLICY]** *(vendor)* The Sky1-Linux driver reads `clock-frequency`
  only from devicetree. Under ACPI it ignores `_DSD` and runs every bus at
  100 kHz. A clean-room driver should use `_DSD` `clock-frequency` (or the
  highest child `I2cSerialBusV2` speed), capped at 400 kHz.
- **[ABI]** `"ClockName"` is informative. There is one clock, so the name
  is not needed to pick it.

### 2.1.2 Devicetree description

`compatible = "cdns,i2c-r1p14"`. Optional `clock-frequency` (Hz, default
100 kHz; Linux falls back to 100 kHz for any value above 400 kHz),
`fifo-depth` (default 16), `resets`/`reset-names = "i2c_reset"`,
`pinctrl-*`. A board devicetree's `clock-frequency` overrides the SoC
default of 400 kHz. Both reference boards set 100 kHz on the PD buses.

## 2.2 Register map

**[HW]** 32-bit registers, only the low bits are used.

| Offset | Name | Access | Content |
|---|---|---|---|
| `0x00` | `CR` | RW | Control (§2.2.1) |
| `0x04` | `SR` | RO | Status (§2.2.2) |
| `0x08` | `ADDR` | RW | Target address, bits [9:0]. Writing it in host mode **starts** a transfer |
| `0x0C` | `DATA` | RW | Write: push one byte into the TX FIFO. Read: pop one byte from the RX FIFO |
| `0x10` | `ISR` | R / W1C | Interrupt status (§2.2.3) |
| `0x14` | `XFER_SIZE` | RW | Receive: bytes still to be received in this chunk. Transmit: bytes still queued in the FIFO |
| `0x18` | – | – | Not used by the host driver |
| `0x1C` | `TIME_OUT` | RW | Bus-hold timeout in SCL periods, 8 bits |
| `0x20` | `IMR` | RO | Interrupt mask: 1 = masked |
| `0x24` | `IER` | WO | Write 1 = enable (unmask) the interrupt |
| `0x28` | `IDR` | WO | Write 1 = disable (mask) the interrupt |

### 2.2.1 `CR`: control

| Bits | Name | Meaning |
|---|---|---|
| 0 | `RW` | Direction of the next host transfer: 0 = transmit, 1 = receive |
| 1 | `MS` | 1 = host (master) mode, 0 = target mode |
| 2 | `NEA` | 1 = normal 7-bit addressing, 0 = extended 10-bit addressing |
| 3 | `ACK_EN` | 1 = send ACK after received bytes (the IP sends NACK on the last one by itself) |
| 4 | `HOLD` | 1 = keep SCL low and do not send STOP at the end of the data. Used for FIFO flow control and for repeated START |
| 5 | – | Not used |
| 6 | `CLR_FIFO` | Write 1 = flush both FIFOs and zero `XFER_SIZE`. Self-clearing |
| 13:8 | `DIV_B` | Second clock divider, 0–63 |
| 15:14 | `DIV_A` | First clock divider, 0–3 |

**[HW]** Host idle value: `ACK_EN` | `NEA` | `MS` with the dividers.

### 2.2.2 `SR`: status

| Bit | Name | Meaning |
|---|---|---|
| 3 | `RXRW` | Target mode only: direction requested by the remote host |
| 5 | `RXDV` | 1 = RX FIFO holds at least one byte |
| 6 | `TXDV` | 1 = transmit data still pending (not needed by the sequences below) |
| 8 | `BA` | 1 = bus active (START seen, STOP not yet seen), from any host |

### 2.2.3 Interrupt bits (`ISR`, `IMR`, `IER`, `IDR`)

| Bit | Name | Meaning |
|---|---|---|
| 0 | `COMP` | Transfer complete: transmit FIFO drained, or the receive chunk finished |
| 1 | `DATA` | Receive: FIFO filled to the data threshold (more data available, transfer continuing) |
| 2 | `NACK` | Target did not acknowledge address or data |
| 3 | `TO` | Bus-hold timeout (`TIME_OUT` expired while `HOLD` kept SCL low) |
| 4 | `SLV_RDY` | Target mode: ready |
| 5 | `RX_OVF` | RX FIFO overflow |
| 6 | `TX_OVF` | TX FIFO overflow (byte written to a full FIFO) |
| 7 | `RX_UNF` | RX FIFO underflow (read from an empty FIFO) |
| 8 | – | Not used |
| 9 | `ARB_LOST` | Arbitration lost to another host |

- **[HW]** `ISR` is write-1-to-clear. Clear it by writing back the value
  read.
- **[POLICY]** Linux enables `COMP`, `DATA`, `NACK`, `RX_OVF`, `TX_OVF`,
  `RX_UNF` and `ARB_LOST` during a host transfer and masks `TO`.

## 2.3 FIFO and transfer size

- **[HW]** FIFO depth: 16 bytes (each direction) on Sky1. The devicetree
  property `fifo-depth` can override it.
- **[HW]** The width of `XFER_SIZE` is a synthesis choice (4–8 bits).
  Probe it: set `CR` = `MS` | `RW`, write `0xFF` to `XFER_SIZE`, read it
  back, then write 0 to `XFER_SIZE` and 0 to `CR`. The read-back value is
  the largest chunk the counter holds. `XFER_SIZE` can only be written
  while `MS` and `RW` are both set.
- **[POLICY]** Linux uses (read-back − 3) as the largest receive chunk,
  which leaves margin for the re-arm in §2.5.3.

> OPEN QUESTION: The probed `XFER_SIZE` width on Sky1 is not recorded in
> the sources. Expect 255 (8 bits) for r1p14. Probe it anyway.

## 2.4 Bit-rate divider

**[HW]** SCL frequency = F_in / (22 × (`DIV_A` + 1) × (`DIV_B` + 1)), with
`DIV_A` ∈ 0…3 and `DIV_B` ∈ 0…63. The fastest possible rate is F_in / 22.

Choosing dividers:

1. Let *p* = F_in / (22 × target). If *p* is 0, or larger than 256, the
   target is out of range.
2. For each `DIV_A` from 0 to 3, take the smallest (`DIV_B` + 1) that
   brings the rate to the target or below, that is
   ceil(F_in / (22 × target × (`DIV_A` + 1))), and skip it if it is not in
   1…64.
3. Keep the pair whose resulting rate is closest to the target **without
   exceeding** it.

- **[HW]** Write the dividers only while the bus is idle.
- **[POLICY]** Linux re-computes the dividers when the input clock rate
  changes, and refuses a rate change that would make the target
  unreachable. Under SCMI the clock rate does not change at run time.

## 2.5 Host transfer sequences

**[HW]** A *message* is one direction to one address. A *transfer* is a
sequence of messages joined by repeated STARTs, ended by one STOP.

### 2.5.1 Before a transfer

1. **[HW]** Wait until `SR.BA` = 0. **[POLICY]** Linux polls every 100 ms,
   for up to 500 ms, then reports "busy" and tries bus recovery.
2. **[HW]** For a transfer of more than one message, set `CR.HOLD` before
   the first message and keep it set until the last message is under way.
   `HOLD` makes the controller finish the message without a STOP, so the
   next address write produces a repeated START.
3. **[HW]** For each message, set `CR.NEA` = 1 for a 7-bit address, 0 for
   a 10-bit address.

### 2.5.2 Transmit (write) message

1. **[HW]** In `CR`: `RW` = 0, `CLR_FIFO` = 1. Set `HOLD` if the message is
   longer than the FIFO depth (or if it is not the last message).
2. **[HW]** Clear `ISR` (write back what was read).
3. **[HW]** Push bytes into `DATA`: as many as fit, which is the FIFO depth
   minus the current `XFER_SIZE`.
4. **[HW]** If all bytes are queued and this is the last message, clear
   `HOLD` now.
5. **[HW]** Write the target address to `ADDR`. This starts the transfer.
6. **[HW]** Unmask the interrupts (§2.2.3).
7. **[HW]** On each `COMP`: if bytes remain, push as many as fit
   (FIFO depth − `XFER_SIZE`). Once nothing remains and this is the last
   message, clear `HOLD`. A `COMP` with nothing left to send ends the
   message.

### 2.5.3 Receive (read) message

1. **[HW]** In `CR`: `RW` = 1, `CLR_FIFO` = 1. Set `HOLD` if the message is
   longer than the FIFO depth (or if it is not the last message).
2. **[HW]** Clear `ISR`.
3. **[HW]** Write `XFER_SIZE` = the message length, or the largest chunk
   (§2.3) if the message is longer.
4. **[HW]** If the whole message fits in the FIFO and this is the last
   message, clear `HOLD` now, right after the address write and before
   the hardware counter can reach zero.
5. **[HW]** Write the target address to `ADDR`. This starts the transfer.
6. **[HW]** On `DATA` or `COMP`: while `SR.RXDV` = 1, read `DATA`. When the
   bytes still expected fall to the FIFO depth or fewer and this is the
   last message, clear `HOLD`, so the controller ends with NACK + STOP.
7. **[HW]** Long reads. The controller NACKs the target as soon as
   `XFER_SIZE` reaches 0, even with `HOLD` set. For a message longer
   than one chunk, re-arm the counter before it runs out:
   - stop draining when exactly (FIFO depth + 1) bytes of the current chunk
     are still expected;
   - wait until `XFER_SIZE` equals (bytes still expected in this chunk −
     FIFO depth), which means the FIFO is full and the bus is held;
   - write the next chunk: the largest chunk if more than that remains
     beyond the FIFO contents, else (bytes remaining − FIFO depth);
   - continue draining.
8. **[HW]** `COMP` with no bytes left ends the message.
9. **[HW]** SMBus block read: the first byte received is the count.
   **[POLICY]** Linux allows for up to 32 data bytes plus the count byte
   (and a PEC byte when used) and trims the message afterwards.

**[HW]** The r1p10 revision of this IP cannot do a repeated START after a
receive message and needs the `HOLD` clear of step 4 done with interrupts
blocked. Sky1 uses r1p14 and has neither restriction.

### 2.5.4 Completion, errors and timeouts

| Condition | Required action | Linux result |
|---|---|---|
| `NACK` | Abort: the controller ends the transfer itself; then reset it (below) | "no device" error |
| `ARB_LOST` | Abort and retry the whole transfer | retry; the I²C core repeats up to 3 times **[POLICY]** |
| `RX_OVF`, `TX_OVF`, `RX_UNF` | Abort and reset | I/O error |
| Received more bytes than requested (counter wrap) | Abort and reset | I/O error |
| No completion in time | Reset | timeout |

- **[HW]** Controller reset (software, not the reset line): mask all
  interrupts (`IDR` = `0x2FF`), clear `HOLD` and set `CLR_FIFO` in `CR`,
  write 0 to `XFER_SIZE`, clear `ISR`, write the value read from `SR` back
  to `SR`.
- **[HW]** After each message, mask all interrupts again.
- **[POLICY]** Timeout per message: the bit time of the message at the bus
  rate plus 500 ms, and at least 1 s. Polled (no-interrupt) transfers allow
  2 s and poll `ISR.COMP` every 10 µs.
- **[POLICY]** Bus recovery (clocking SCL until SDA is released) uses a
  GPIO mode of the pads. Linux only does it when the devicetree supplies
  pin states. Under ACPI it is not available.

### 2.5.5 Supported functions

**[POLICY]** Linux reports: plain I²C, 10-bit addressing, all SMBus
transactions except QUICK (zero-length write), and SMBus block read.

## 2.6 Hardware timeout quirk

**[HW]** In host-receive mode, the IP can produce a bogus read after its
bus-hold timeout fires. The timeout cannot be turned off. Write `0xFF`
(the maximum) to `TIME_OUT` whenever the controller is initialised and
keep the `TO` interrupt masked.

## 2.7 Initialisation and power management

1. **[HW]** Enable the clock, release the reset.
2. **[HW]** Probe the transfer size (§2.3).
3. **[HW]** Compute the dividers (§2.4) and write `CR` = `ACK_EN` | `NEA` |
   `MS` | dividers.
4. **[HW]** Write `TIME_OUT` = `0xFF`.
5. **[HW]** The register state is lost when the clock or the FCH domain
   goes away. Redo steps 3–4 every time the controller is brought back.
6. **[POLICY]** Linux gates the clock after 1 s idle (runtime suspend). It
   does system suspend in the no-IRQ phase, so that I²C stays usable by
   other drivers' late suspend steps.
